Next code: `G-ORBITAL-COMPILER-013`

- **G-ORBITAL-COMPILER-012** [mechanical] — A `persist` row may carry a key its entity does not declare when the row is built with `object/merge`: std-crm-experience `NotePersistor` (`persist create Note (object/merge ?data { author: …, createdAt: … })`, `experience/organisms/std-crm-experience.lolo:793`) and std-field-service-experience (`persist create WorkOrderRow`, line 371) write `createdAt` into entities that declare no `createdAt`, and both validate 0/0. The persist-row type check (`validate_persist_row_types`, `phases/validation/expressions/effect/set.rs`) compares only declared fields, so an undeclared key in the row's static record type passes unseen and the store keeps or drops it depending on the host. Found 2026-11-12 while making the mock stampers write only declared timestamp fields (G-ORBITAL-CORE-153). Fix: the same check refuses a row key the entity does not declare when the row's record type is known; then declare `createdAt` on both entities or drop the key. Prevention rung: (2) `orb validate`. Severity: medium. Root cause: one-off.
- **G-ORBITAL-COMPILER-011** — `inline::drop_unreferenced_colliding_auxiliaries` decides whether an auxiliary entity that collides with another orbital's primary is still referenced by serializing the orbital's whole trait list to JSON and substring-searching it for the entity name (`trait_blob_mentions`): a text-matching heuristic (a name inside a string literal or description keeps the entity; a reference spelled any other way drops it). It should walk the traits' typed references (linked entity, `fetch`/`persist` entity, payload `entity` markers, relation targets) instead. The serialization is now built only when a collision exists (2026-11-07, project-friday profile); the heuristic remains. orbital-compiler [mechanical] — repro: an auxiliary entity named only inside a trait description survives the drop; prevention rung: (2) a unit test pairing a description-only mention (dropped) with a typed reference (kept). Severity: medium. Root cause: one-off.
- **G-ORBITAL-COMPILER-010** [mechanical] — `orb resolve` writes an imported trait's `sourceBehavior.behavior` as an ABSOLUTE filesystem path (e.g. `/Users/<you>/…/test/fixtures/programs/stat-card`) where the v1 output carried the import as written (`./stat-card`), so a resolved program is machine-specific and committed fixtures leak the author's home directory (found 2026-11-07 regenerating renderers/web test/fixtures/programs/{canvas-view,event-wires}.orb.json; canvas-view.test.ts now compares `basename`). Fix: record the import relative to the program (or the package-qualified behavior id), one spelling. Rung: (3) a fixture/golden must be reproducible across machines. Severity: medium. Root cause: T3.

- **G-ORBITAL-COMPILER-009** [mechanical] — A type guard does not narrow: `(if (validate/string @t) (as @t string) …)` types the `as` branch `string?`, because `as` is a checked narrowing that is null on mismatch and `validate/string` proves nothing to it, so a guarded read can never be non-null without a hand-written null check (found 2026-11-07 fixing G-STD-293: `packages/almadar-std/behaviors/lolo/ui/core/atoms/std-tag-strip.lolo:46` and five more arms now spell `(let ((s : string? (as @t string))) (if (= @s null) … [@s]))`). Fix: `validate/<type>` guards narrow their operand in the true branch (inference `presence`/narrowing), so `(as @t string)` under that guard is `string`. Rung: (1) the type system. Severity: medium. Root cause: A4.




- **G-ORBITAL-COMPILER-005** [mechanical] — `orb validate` rejects a list literal of a narrowed binding in an emit payload: with `(let ((p0 (bytes/write-uint 0 4 "le"))) (if (= @p0 null) … (emit GPU_STEP { params: [@p0] })))` and `GPU_STEP { params : [bytes]! }`, it reports ORB_EMIT_PAYLOAD_FIELD_TYPE_MISMATCH "has a list item of type 'bytes', declared as '[bytes]'", comparing the item with the whole list type; the same value built as `(array/map (array/range 1) (fn k @p0))` passes. Found writing almadar-behaviors std-physics-fluid-sph (LEARN_RESET), which carries the array/map spelling until this is fixed. Prevention rung: `.lolo` type system (the emit payload check's list-literal element compare). Severity: medium. Root cause: one-off.


- **G-ORBITAL-COMPILER-004** [mechanical] — `orb validate` accepts a render-ui `children: [ … ]` literal whose element is itself a list (`(array/map …)`, `array/filter`, a nested `[ … ]`), which the web flattens and the native host does not, so the hosts disagree (std-slide-deck, std-stat-rows; fixed in std 2026-11-06). Fix: the render-ui child-position type check refuses a list-typed element and suggests `children: (array/map …)` or `(array/concat …)`. Prevention rung: (2) `orb validate`. Severity: medium. Root cause: A2.


- **G-ORBITAL-COMPILER-001** [mechanical] — A routed listen's `when` and `with` read `?field` from the event it hears, and `orb validate` never checks those reads against that event's payload: `A.PING -> GOT when (> ?zzz 0) with { size: ?zzz }` validates 0/0 although PING declares only `size`, and so does `$MOUNT -> SEED_PAGE when (> (array/len ?missing) 0)` against the kernel's `$MOUNT { page, route, traits, entities }` (found 2026-11-04 adding the `$MOUNT` listen). The read is null at run time. Owners: orbital-compiler validation (resolve the heard event's payload: the source trait's declared emit, or the kernel's `$MOUNT` shape from orbital-core) or the std listen lints. Repro: the two probes above under `.orbital/probe/`. Prevention rung: (2) `orb validate`. Severity: medium. Root cause: A2.
